# Администрирование и устройство UNKNOWN SMP

## Архитектура

Один JAR и 38 внутренних модулей (`/usmp status` показывает их состояние). Модули объявляют, от каких модулей зависят. Если модуль падает при запуске или во время работы:

- ошибка пишется в консоль и в `plugins/UnknownSMP/logs/errors-ДАТА.log`;
- персонал с правом `usmp.admin.monitor` получает уведомление;
- команды и кнопки модуля отвечают «временно недоступно», зависимые модули тоже блокируются;
- остальные модули работают, данные не удаляются.

Если не поднялась база данных или авторизация, вход на сервер блокируется, чтобы не потерять данные.

## Данные и защита от дюпа

- Источник истины — база данных. Деньги меняются только SQL-операцией, которая сама проверяет остаток (`balance >= сумма`), и каждое изменение пишется в `money_log`. Кэш обновляется только после успешной транзакции.
- Все записи выполняются по очереди в одном потоке записи. Связанные изменения (покупка лота: списание, зачисление, удаление лота, доставка) идут одной транзакцией.
- Предметы с рынка сначала попадают в почту (запись в БД), а в инвентарь выдаются после атомарного удаления записи. После каждой операции с предметами инвентарь игрока сразу сохраняется на диск.
- Меню блокируется на время операции. Повторные клики, перетаскивание и shift-клики в чужие слоты отклоняются.
- У уникальных предметов есть скрытый UID и HMAC-подпись. Подделки и дубликаты попадают в журнал как подозрительные; автоматически ничего не удаляется.
- Дуэли: перед входом инвентарь SMP записывается в таблицу `duel_stash`, восстановление полностью перезаписывает инвентарь, поэтому повторное применение после сбоя не создаёт копий. Предметы дуэлей помечены и изымаются при выходе из мира дуэлей.

## База данных

- **SQLite** (по умолчанию): `plugins/UnknownSMP/data.db`, режим WAL.
- **PostgreSQL**: `database.yml → type: postgresql` и параметры подключения.
- Схема версионная (таблица `usmp_schema`, сейчас v2). Перед миграцией существующей базы автоматически создаётся копия и проверяется. При ошибке миграция откатывается, и сервер не стартует с повреждёнными данными.
- Основные таблицы: `accounts`, `players`, `player_stats`, `unlocks`, `homes`, `money_log`, `auction_lots`, `orders`, `mail`, `clans`, `clan_members`, `wars`, `unique_items`, `quest_progress`, `punishments`, `reports`, `block_log`, `action_log`, `duel_stash`, `world_state`.

### Перенос SQLite → PostgreSQL

1. `/usmp backup now`.
2. Остановите сервер, в `database.yml` укажите `type: postgresql` и параметры, запустите (создастся пустая схема).
3. `/usmp backup restore ИМЯ db`, затем перезапуск: данные из `database.db` копии будут импортированы в PostgreSQL.

## Резервные копии

Каждая копия — папка `backups/ДАТА_метка/`:

- `database.db` (SQLite через `VACUUM INTO`) или `database.dump.gz` (PostgreSQL, переносимый дамп);
- `config.zip` — все `.yml`;
- `worlds.zip` — миры (перед копированием сохраняются, автосохранение на время копирования выключается);
- `manifest.properties` — контрольные суммы SHA-256.

После создания копия проверяется: контрольные суммы, `PRAGMA integrity_check`, полное чтение архивов и пробный импорт дампа в память. Неудачная копия помечается `FAILED.txt`, администраторы получают уведомление. Ротация удаляет самые старые копии сверх `keep`.

### Восстановление

1. `/usmp backup list`, затем `/usmp backup verify ИМЯ`.
2. `/usmp backup restore ИМЯ db` (или `worlds`, `configs`, `db,worlds,configs`). Отменить: `/usmp backup cancel`.
3. Перезапустите сервер. Восстановление применяется до загрузки миров; текущие данные переносятся в `backups/pre-restore-ДАТА/`, ничего не удаляется.

## Журналы и откаты

- Пишутся: установка и разрушение блоков (вместе с содержимым сломанных контейнеров), взрывы с источником, действия в контейнерах (что взяли и положили), выброс и подбор предметов, команды (пароли скрыты), сделки, баланс, смерти, события, админ-действия, банк кланов, ошибки транзакций, подозрительные действия.
- Просмотр: панель владельца → Журналы, `/usmp lookup`, инспектор блоков `/usmp inspect`.
- Откат только вручную: `/usmp rollback Ник 2h [радиус]` → предпросмотр (сводка и список изменений) → подтверждение. Восстанавливаются блоки и содержимое контейнеров, результат пишется в журнал.

## Режим обслуживания

`/usmp maintenance on 60 Обновление`: новые входы закрыты (кроме персонала), торговля и банки на паузе, плагин ждёт, пока запишется очередь БД, и через 60 секунд отключает игроков. `/usmp maintenance off` — снять.

## Сборка из исходников

```
./gradlew build
```
Готовый файл: `build/libs/UnknownSMP-1.0.0.jar`. Нужна Java 21. Зависимости: Paper API 1.21.11, HikariCP 6.2.1 (Apache 2.0) и PostgreSQL JDBC 42.7.4 (BSD-2) — обе библиотеки вложены в JAR. SQLite JDBC (Apache 2.0) берётся из Paper.
